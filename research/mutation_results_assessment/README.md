# Prespecified workflow fault-detection experiment

This directory preserves assessment A, performed before the test assertions were strengthened in response to PIT findings. `assertion_assessment_link.json` records the hashes of both test versions and their shared case identities. Assessment B extends the checks within the same 115 workflow cases. It also supplies the optional matching hive identifier in existing treatment requests and redelivers the existing harvest event in the durable-rejection case. The test-resource files remain identical.

To reproduce A, create an isolated copy of the final source tree and run the following commands from that copy. The patch is stored in the A-to-B direction, so reversing it restores the A test class.

```sh
git apply --check --reverse research/mutation_results_assessment/assertion_strengthening.patch
git apply --reverse research/mutation_results_assessment/assertion_strengthening.patch
sh ./gradlew test --no-daemon
python research/archive_verification.py
python research/run_workflow_mutations.py --work-dir ../manual-assessment-a
python research/summarize_workflow_mutations.py
```

On Windows use `.\gradlew.bat` for the Gradle command. The work directory for the mutation runner must be new or empty. Generated mutation results are written to `research/mutation_results` in that isolated copy. The archived results below retain their original assessment A observations.

The unmodified baseline passed 167 cases, including 115 workflow HTTP/PostgreSQL cases, 43 decision-comparison and structural-transfer cases, and 9 service cases. Each of the ten specified faults was then applied separately to an isolated source copy, using the same 115 workflow cases. The 25 dedicated cases include 12 wintering regressions.

| ID | Fault | Failures in matrix (90) | Failures in dedicated cases (25) | Outcome |
|---|---|---:|---:|---|
| M01 | Include the withdrawal endpoint | 0 | 3 | detected |
| M02 | Exclude the treatment start | 0 | 2 | detected |
| M03 | Include the administration endpoint | 0 | 2 | detected |
| M04 | Require every active treatment to be in administration | 4 | 1 | detected |
| M05 | Retain expired treatment state | 4 | 3 | detected |
| M06 | Remove the wintering harvest guard | 5 | 12 | detected |
| M07 | Throw after recording business rejection | 22 | 16 | detected |
| M08 | Remove explicit per-hive write lock | 0 | 1 | detected |
| M09 | Keep nanoseconds in harvest event time | 0 | 1 | detected |
| M10 | Omit transition event association | 30 | 13 | detected |

The matrix detected 5/10 specified faults. The complete integration suite detected 10/10. This is descriptive attribution within the selected fault set; no test assertions were added or changed after observing outcomes.

`manifest.json` and M01–M10.patch define all planned faults. M01–M10.json retain every executed test identity and outcome; `summary.json` also retains non-detection categories. `test_group_attribution.csv` is generated by `research/summarize_workflow_mutations.py`. The manually reviewed `independent_failure_review.csv` connects observed failures to specific assertions and documents interpretation limits.

The causal review records the actual failing observation and its location for each variant. In M07 a business rejection becomes an exception. Tests may fail at the HTTP assertion or while decoding a decision identifier from the error response. M08 removes the lock annotation used by both the command and the controlling transaction in its test. Its observable missing lock wait supports a protocol violation, not an independently observed incorrect harvest decision under concurrency. These results are not a correctness proof or an exhaustive assessment of mutation operators or interleavings.

Raw logs and source copies remain in the local work directory and are not part of this publication artifact. Patch files use LF line endings; their byte SHA-256 values match the manifest. See ../README.md for reproduction.
